Working notes for translator·console + the ESP32-S3 watch firmware.
Repo: https://github.com/wytanj/beagledex.git
Last updated 2026-08-11.

## Where this is

Running on device `28848590ba0c` right now: **`watch` 0.6.0** — the app shell, with
Clock / Ask / System, swipe navigation, a shared push-to-talk service, idle sleep,
and swipe-down quick settings.

Verified working end to end:

- **Console** — Nuxt 4, three pages, file-backed store in `.data/db`. Records every
  flash, because `flash.mjs` writes the record rather than a human.
- **Panel** — CO5300 368×448 over QSPI, `Arduino_CO5300`, `col_offset1 = 16`.
- **Touch** — CST820 at `0x15`, polled. Coordinates are identity-mapped to the panel;
  no calibration layer needed.
- **Audio** — ES8311 up at 16 kHz, gain 2, half-duplex capture into PSRAM.
- **Sleep** — dim at 15 s idle, `displayOff()` at 45 s, wake on touch or button.
  Measured on device at 15.004 s and 45.002 s. `displayOff` is the part that
  matters: brightness 0 alone leaves the AMOLED controller self-refreshing.
- **Buttons** — BOOT: tap locks or wakes, double tap changes app, hold captures
  voice (works from locked). Double tap is app-switching deliberately, so a dead
  touch panel cannot strand you in one app.
- **Quick settings** — swipe down from the status strip: brightness, sleep
  timeout, lock now. Only swipes starting above y=90 open it, so in-app vertical
  swipes stay available.
- **Partitions** — clean A/B (`ota_0`/`ota_1`, 3 MB each), written and read back
  byte-identical. `nvsfactory` untouched.
- **Logging without a network** — `npm run log` bridges serial into the store, so
  `/devices/:id` tails device activity with no WiFi and no web server.
- **Config push** — `npm run push time|app|tok|clear` drives the running firmware
  over serial. These are the verbs the web UI will drive later.

Quick reference:

```bash
npm run dev                  # console at localhost:3000
npm run watch:build          # compile firmware/watch
npm run flash -- --port COM3 --bin firmware/watch/build/watch.ino.bin --version X.Y.Z --features ...
npm run log                  # serial → .data/db (records what happened)
npm run monitor              # serial → terminal only (records nothing)
npm run push time            # set the RTC from this machine's clock
```

## Next up, in order

1. **Phase 3 transport.** The one thing standing between this and a working device.
   `/api/translate` has a frozen contract already returning 501, and the token sink is
   already shaped like a stream — so this is: WiFi provisioning, then POST capture,
   then feed `tokAppend()` from the response instead of from serial. Do it over WiFi
   first even though the product wants BLE; same contract, far faster to iterate, and
   swapping transport later touches one function.
2. **Config API + device-page form, reading and writing `config/devices/<id>.json`.**
   Settings are git-tracked files, not a database — see "Settings live in git" in the
   README. `GET/PUT /api/devices/:id/config` should read and write that file directly, so
   the dashboard is an editor for a tracked file and `git log` is the audit trail. Two
   existing gaps close here: `register` already promises to preserve "the name and notes
   you typed" with no UI to type them, and the README already admits the channel/pin UI
   is missing.
   Also wants a **face editor**: drop an image, crop, position the time, and preview it.
   The preview is exact rather than approximate because the browser and the device consume
   the same converted blob — `scripts/face.py preview` already round-trips it, verified.
3. **Settle the microphone.** Peak has fallen 259 → 176 → 67 across boots and L now
   reads exactly equal to R, which a quiet room does not explain. Nothing has spoken
   through that mic since the battery was detached. The Ask app prints `no mic signal`
   on screen, so this is now a two-second check. If it is dead, first suspect is an
   AXP2101 rail that reset to defaults when the battery came out.
4. **Replace the battery read — it is measurably wrong, not merely unverified.**
   `0xA4` reported **100% within minutes of the cell being reported at 1%**, which no
   lithium cell does. It is either not the percentage or it saturates while VBUS is
   present. This blocks power work: you cannot measure an optimisation with a broken
   gauge. Until it is fixed the only trustworthy metric is **wall-clock hours to
   shutdown on battery**. Fixing it means reading the battery voltage ADC and
   converting — which needs a register verified against two sources first.
5. **Phase 5, OTA + rollback.** The A/B table exists for this. Note `ota_1` currently
   holds fragments of the old vendor app with no valid image header — the bootloader
   correctly refuses it, but don't treat that slot as empty-and-ready until something
   has actually written to it. Also needs binary hosting: `/api/ota/check` returns
   `url: null` today.
6. **Phase 6, BLE phone relay.** The product shape — phone does the heavy lifting,
   device is a token transmitter plus UI. Should speak the same contract as (1).
7. **Derive `--version` from the sketch.** 0.6.1 was flashed with `--version 0.6.1`
   while `FW_VERSION` in the source still said `0.6.0`, so the build record and the
   running firmware disagreed. The console caught it — that is what the shipped-vs-active
   diff is for — but `flash.mjs` should read `FW_VERSION` out of the sketch (or refuse to
   flash when the two disagree) so the flash history cannot be wrong in the first place.
   That is the whole premise of the record being written by the thing that moved the bytes.
8. **Light sleep**, once (1) gives the device a transport other than USB serial. See the
   power notes below; it is the ~50× lever, worth far more than every other item here.

## Open questions

- **Mic path** — see 3 above. Blocks anything that depends on captured audio meaning
  something.
- **Battery register** — see 4.
- **Which PMIC interrupt bit is the PWR button.** PWR is wired to the AXP2101's
  PWRKEY, not a GPIO, so `digitalRead` cannot see it. Waveshare call it
  customisable but publish neither register nor method. `pmicIrqPeek()` logs
  status bytes `0x48..0x4A` read-only on change; the current baseline is
  `10 AB 48`, so **press PWR and see which bit moves**. Making it usable then
  needs one write to clear the latch — not going in until the bit is confirmed,
  because that chip owns the system rails. Until then the device has one usable
  button, which is why BOOT carries three actions.
- **microSD pins.** Genuinely unestablished: not in either source that gave us
  everything else, not on the Waveshare docs page, and the vendor's own SD example
  includes the `pin_config.h` their repo doesn't ship. Leads in order: the
  schematic PDF on files.waveshare.com, xiaozhi's board config, the vendor
  example. The `cacheReady()`/`cachePut()`/`cacheGet()` seam in `watch.ino` is
  already in place, so the card is a fill-in rather than a refactor.
- **Gesture engine** — the CST820 reports gesture `0x00` for everything when polled.
  Swipes are derived from coordinates instead, which is fine and arguably better. If
  native gestures are ever wanted, `0xEC` (MotionMask) is the lead, and it may need the
  interrupt line — for which no pin is recorded anywhere.
- **Timezone** — the PCF85063 has no timezone field, so whatever `push.py time` writes
  is what the Clock shows. Wants a real answer once config exists.
- **Per-device tokens** — one shared `DEVICE_TOKEN` today. A phone relay makes this
  real; `esp_ds` on the S3 signs with a key firmware cannot read.

## Settled — don't re-derive these

Each cost real time. The evidence is in the files, not just in someone's memory.

- **This is a v2 board.** Three independent confirmations: `co5300` appears 33× in the
  factory image and `sh8601` zero times; nothing answers at `0x38` (no FT3168); the
  touch chip ID reads `0xB7`. Assume v2 parts throughout. — `firmware/pin_config.h`
- **App images go to `0x110000`** (`ota_0`, formerly `factory`). `0x10000` is inside
  `nvs` on this layout and bricks the app. — `firmware/README.md`
- **Never erase the whole chip.** `nvsfactory` at `0x9000` holds per-unit calibration
  present in no vendor download. `flash.mjs` refuses the flag.
- **Use `--no-stub`.** The stub flasher desyncs on this board's USB-Serial/JTAG bridge.
- **`CDCOnBoot=cdc` is mandatory**, or `Serial` goes to the UART pins and the board looks
  dead over the cable you just flashed it with. Baked into the `build.mjs` FQBN.
- **No live loopback on this hardware.** Mic and speaker are centimetres apart with no
  echo cancellation; a live loopback saturates. Capture is half-duplex by design.
- **Never repaint during audio capture.** Quad PSRAM plus a PSRAM capture buffer means
  display traffic during capture causes crackle. The shell enforces this in
  `pttService()` via `audioBusy`.
- **Types used in `.ino` function signatures must come from a header.** The Arduino
  preprocessor hoists prototypes above sketch-level declarations. — `shell_types.h`
- **The screen is not a power indicator.** Nothing drives the panel in phases 00–01, and
  a long button press drops the panel rail through the AXP2101 while USB keeps the ESP32
  running. Diagnose from serial or the VID/PID, never from the screen.

## Deliberately not doing

- **LVGL.** A 368×448×2 framebuffer is 322 KB in quad PSRAM, for widgets a watch face
  and a token stream don't need. Immediate-mode `Arduino_GFX` is the right size.
- **Waveshare's `ui_a`/`ui_b`/`ui_c` demo UIs.** Never linked; that's the bloat.
- **A live level meter during capture.** It would be the one feature guaranteed to
  corrupt the recording it displayed.
- **Special-casing translation.** It's an Ask with a different prompt. Keeping it
  unremarkable is what makes the shell worth having.
- **Light-sleeping the SoC.** It would save more than screen-off does, but it drops
  the USB-Serial/JTAG link — currently the device's only transport, and the thing
  carrying tokens, config and logs. Revisit once phase 3 gives it another way to
  be reached. Same reasoning rules out CPU frequency scaling for now.
- **Guessing PMIC writes.** Reads are free; writes to the chip holding the system
  rails are not. Everything AXP2101 stays read-only until verified.
